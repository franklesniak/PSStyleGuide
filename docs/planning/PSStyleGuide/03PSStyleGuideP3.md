# Remediate Markdown lint dependency advisories and add npm update governance

## Summary

Upgrade the Markdown tooling under `.github/workflows` to deliberately reviewed
maintained releases, define a finite supported Node set, select one exact npm
CLI for every runtime cell, preserve the repository's full/nested/staged lint
semantics, prove the real installed pre-commit hook, resolve or continuously
govern every npm audit finding, and add review-only npm updates.

This issue owns the final Node/npm/package/hook/Dependabot policy. It does not
infer contributor support from an action's internal JavaScript runtime and
does not weaken P1/P1A/P1B publication controls.

## Dependencies and order

Implement P3 after:

1. P1 — deterministic generator/runtime/action foundations;
2. P1A — workflow-inert candidate validator/context/harness;
3. P1B — final immutable candidate and verified writer; and
4. P2 — blank-line visualization/source/generated update.

Record P2's real blocked-by relationship and exact P1/P1A/P1B/P2 merge
commits. This slate is worked in that one order. Do not perform a partial
package update outside P3 or maintain an alternate dependency graph.

At implementation start, re-read current package/lock/hook/lint/workflow/
Dependabot state and rerun the audit. Do not treat the dated baseline below as
acceptance.

## Dated baseline, not acceptance

On 2026-07-29, `npm audit --package-lock-only --json` under Node 26.5.0/npm
11.7.0 returned exit 1, report version 2, and metadata totals of five high and
two moderate vulnerability properties. The seven property names were:

- `brace-expansion`;
- `js-yaml`;
- `linkify-it`;
- `markdown-it`;
- `markdownlint-cli2`;
- `minimatch`; and
- `picomatch`.

Those properties contained fourteen object advisory records at observation
time. Property count, object-advisory count, and installed node-path count are
different units. Advisory URLs/package graph evidence—not the dated aggregate—
drive implementation.

The observation runtime is inspection evidence only, not a proposed supported
P3 cell.

## Requested changes

### 1. Recompute dependency and advisory inventory

From a clean clone at exact prerequisite commits record:

- Node/npm executable paths and full versions;
- `package.json`, lockfile version, root declarations;
- `npm ls --all --json`;
- `npm outdated --json`;
- raw `npm audit --package-lock-only --json` and exit;
- direct release/engine/changelog/license/provenance evidence;
- lint scripts/config/nested imports;
- exact installed hook behavior;
- P1B final action roles; and
- P2 source/generated byte baseline.

Normalize audit evidence separately as:

- vulnerability-property/package identity;
- every object advisory URL/source ID, severity/range;
- exact package-keyed `nodes` set;
- `via`/`effects` dependency edges;
- installed lockfile package/version for every node;
- direct parent/context;
- `fixAvailable` shape;
- chosen disposition; and
- evidence date/exact npm version.

Do not cross-product advisory URLs with node paths. Use exact
`(Package, AdvisoryUrl)` as approval identity and keep `AuditNodePaths` as a
separate exact package-keyed set.

### 2. Select maintained compatible packages deliberately

For every direct dependency:

- find maintained releases compatible with all lint surfaces;
- review intervening major releases, especially pre-1.0 major-minor changes;
- verify license, provenance, package contents, and `engines.node`;
- document config/API changes; and
- justify retain/upgrade/replace/remove.

Edit `package.json` explicitly and regenerate lockfile version 3 from clean
state with the selected exact npm. Never use `npm audit fix --force`, `--force`,
`--legacy-peer-deps`, ignored engines, or manual lock edits.

Require clean `npm ci`, `npm ls --all` with no invalid/extraneous/missing node,
exact root/lock agreement, preserved outer/nested/staged intent, and a second
reproducible clean install.

### 3. Select and enforce one exact npm CLI

Choose one maintained exact npm release whose own Node engine admits every
final supported Node line and patch floor.

Record one normative npm version and:

1. install/resolve that exact CLI in every local/hosted cell;
2. assert exact npm version;
3. prove npm's `process.execPath`/`process.versions.node` uses the selected
   active Node;
4. use only that npm for lockfile generation, `npm ci`, `npm ls`, audit, both
   lints, and real hook tests;
5. designate exact preferred Node 24/npm as the sole lockfile producer unless
   evidence justifies another supported pair; and
6. make every other cell prove no lockfile rewrite.

Record exact Node/npm pairs. If no one maintained npm supports all selected
Node lines, stop and revisit the Node set or explicitly redesign/document
multiple reviewed CLIs. Do not claim one npm while using bundled variants.

Add an npm engine declaration if it accurately communicates the contract. Do
not add a package-manager field merely for appearance.

### 4. Declare one finite Node policy

After package/npm selection, choose exact reviewed supported LTS lines. Expected
default:

- selected supported minimum: Node 22 with any required patch floor; and
- preferred hosted line: Node 24 with any required patch floor.

Express the final set as a finite semver union in `engines.node`. For a 22/24
policy it must admit reviewed Node 22 and 24 releases while excluding 23, 25,
current 26, and unreviewed future majors. Never use an open-ended minimum or
contiguous range that admits an intervening unsupported major.

Make `.husky/pre-commit` and
`.github/workflows/lint-staged-markdown.mjs` implement the same finite
decision. If one shared dependency-free implementation is impractical across
shell/Node, use identical fixtures and prove the decisions equal.

Test:

- lowest admitted and normal current patch on each supported major;
- one below each patch floor;
- below-minimum major;
- every intervening unsupported major;
- current/above-maximum unreviewed majors;
- empty, malformed, prefix/suffix, whitespace, and extra-component forms.

Do not encode the durable rule as “even majors”; Node's announced post-26
release cadence makes that an unstable synonym for LTS.

### 5. Preserve and prove full/nested/staged lint behavior

The pre-commit hook:

1. preserves staged-Markdown skip behavior;
2. resolves `node` and exact selected npm as applications;
3. queries actual Node before package/binary checks;
4. applies exact finite support decision without `node_modules`;
5. rejects malformed/unsupported/future versions before npm/lint;
6. emits stable observed/accepted/remediation diagnostics;
7. retains GUI Git/version-manager guidance through
   `~/.config/husky/init.sh`;
8. discloses deliberate `--no-verify` as bypass, never success; and
9. invokes the repository's programmatic staged-content API only after runtime
   and tooling validation.

Preserve classifications:

- no staged Markdown: zero without npm;
- valid staged Markdown: zero;
- lint finding: reject with rule/path;
- tooling/config/runtime failure: reject distinctly;
- unexpected native/npm failure: preserve status in diagnostics.

Do not replace PSStyleGuide's staged-content API with TerraformStyleGuide's
different full-lint hook.

### 6. Add a tracked cross-platform lint/hook harness

Create `Test-LintStagedMarkdown.ps1` with `#Requires -Version 5.1`, exact script
version, and explicit repository path. It creates disposable repositories and
indexes only; never mutates the implementer's index/hooks/config/worktree.

Mandatory stable IDs:

| ID | Behavior |
| --- | --- |
| `NPM-01` | clean install and valid complete tree |
| `LINT-01` | outer lint success |
| `LINT-02` | nested lint success |
| `HOOK-01` | no staged Markdown skips without npm |
| `HOOK-02` | staged valid Markdown passes |
| `HOOK-03` | temporary outer violation rejects with exact rule/path |
| `HOOK-04` | temporary nested-fence violation rejects with exact rule/depth/path |
| `HOOK-05` | staged-only API lints staged content, not unrelated worktree bytes |
| `HOOK-06` | missing npm/tool rejects as tooling failure |
| `HOOK-07` | broken config/startup differs from lint finding |
| `HOOK-08` | unsupported/malformed/future Node rejects before npm/lint |
| `HOOK-09` | clean-installed Husky hook invoked by real `git commit` passes/rejects and leaves expected index/commit |

At least one case performs clean install, stages test-owned Markdown, invokes
`git commit` without directly calling `.husky/pre-commit`, proves installed
Husky invocation, and verifies cleanup/source repository unchanged.

Run the harness on:

- Ubuntu selected-minimum Node;
- Ubuntu preferred Node 24;
- Windows/Git Bash selected-minimum Node; and
- Windows/Git Bash preferred Node 24.

PowerShell may orchestrate; the real hook executes in Git/Husky shell. Record
shell, Git, Node, npm, package, and harness versions.

### 7. Add a tracked audit-policy validator

Create `Test-NpmAuditPolicy.ps1` with `#Requires -Version 5.1`, exact script
version, explicit repository/package/lock/exception paths, and exact selected
npm application.

It:

1. runs `npm audit --package-lock-only --json`;
2. captures raw JSON and native exit immediately;
3. treats only reviewed vulnerability exit separately from registry/tool
   failure;
4. requires report version 2 and validates every consumed field/type;
5. validates metadata counts against vulnerability properties;
6. validates property name/severity/range/isDirect, array `via`/`effects`/
   `nodes`, object advisory URL/severity/range, string graph links, and Boolean
   or reviewed-object `fixAvailable`;
7. validates reciprocal graph targets;
8. resolves every node path to matching package/version in lockfile;
9. derives unique `(Package, AdvisoryUrl)` residual keys;
10. keeps exact package-keyed node sets separate;
11. validates native exit against derived actionable set; and
12. emits no package contents/secrets.

Preserve raw report and exact npm version in bounded failure evidence so schema
or registry changes fail clearly.

### 8. Resolve or govern every advisory

Preferred result: zero vulnerabilities at all severities.

If clean:

- `npm-audit-exceptions.json` is absent; and
- validator rejects an empty/stale exception file.

If a residual cannot be removed compatibly, conditionally add the structured
exception file. Each record contains:

- exact package and advisory URL/source ID;
- severity/CVSS when supplied;
- exact package-keyed `AuditNodePaths`;
- exploitability for this repository;
- compensating controls;
- accountable owner;
- UTC creation and invariant expiration;
- real public PSStyleGuide follow-up issue URL, not a PR;
- approval identity/date; and
- evidence no maintained compatible fixed tree exists.

Require exact equality: no missing, extra, duplicate, expired, stale,
topology-changed, or already-fixed record. Expiry is future and within
repository maximum. CI fails after expiry or topology change.

### 9. Establish final Dependabot governance

Normalize `.github/dependabot.yml` to exactly two review-only entries:

1. `github-actions` at `/`; and
2. `npm` at `/.github/workflows`.

Use approved schedules. Reject duplicate/extra ecosystems, wrong directories,
unapproved ignores, and auto-approval/merge.

Dependabot proposals require CI, changelog/license/provenance/engine review,
lockfile review, exact npm/Node cells, real hook evidence, and audit policy.
They never bypass immutable action roles.

### 10. Update the final Markdown workflow role policy

Retain P1B action SHAs and all enduring build workflow roles. Update the sole
normative role table atomically for the final Markdown Node matrix/job layout:

- exact supported-minimum and preferred Node 24 setup roles;
- exact checkout refs/persistence;
- automatic package-manager cache disabled;
- exact conditions and complete inputs; and
- no unreviewed action.

Run clean install, tree validation, audit policy, required lint/hook harness
work in every claimed cell. The preferred Node 24 cell also runs the complete
outer/nested lint, P1A helper harness, and any P2 permanent content evidence.

### 11. Revalidate enduring behavior and declare supersession

Enduring and green:

- deterministic LF/BOM-less generator;
- P1A paths/limits/context/cleanup/stable IDs;
- immutable artifact ID/digest;
- action pins/permissions/events;
- four unique attestations/terminal approval;
- at-use writer regeneration/identity/lease/token boundary;
- P2 source/generated content;
- outer/nested/staged lint semantics; and
- generated artifact bytes.

Replaced by P3:

- package/lock content;
- Node/npm/contributor policy;
- hook runtime guard;
- Markdown Node job/matrix roles; and
- one-entry Dependabot intermediate state.

Earlier affected-file counts are one-time gates, not enduring behavior.

## Validation

From fresh clones/clean dependency state:

1. run exact selected npm on minimum/preferred Node and both OS families;
2. record executable/full versions and enforce strict engines;
3. scope/restore `CI=true` around `npm ci`;
4. run two clean reproducible installs;
5. run `npm ls --all`;
6. run outer/nested lints;
7. run every staged/hook stable ID;
8. invoke at least one real installed hook per OS family;
9. run raw/human-readable audit and tracked policy validator;
10. validate absent or exact exception file;
11. validate exact two-entry Dependabot;
12. validate final action roles;
13. rerun P1/P1A/P1B/P2 enduring evidence;
14. regenerate and require unchanged four artifacts;
15. require exact changed/staged equality to computed P3 path set; and
16. rerun from staged content with no additional diff.

Capture required PR cells and one post-merge push proving the publication
pipeline remains correct.

## Acceptance criteria

- [ ] Maintained direct packages are justified and reproducibly installed
      without force/engine bypass.
- [ ] Lockfile version/tree exactly matches manifest; `npm ls --all` passes.
- [ ] One exact npm CLI is used in every claimed Node/OS cell.
- [ ] `engines.node`, hook, staged API, workflow roles, and tests enforce one
      finite supported set.
- [ ] Unsupported intervening/current/future majors fail before npm/lint.
- [ ] Outer, nested, and staged semantics remain correct.
- [ ] Every lint/hook stable ID passes on both Node roles and OS families.
- [ ] Real clean-installed Husky hook is invoked by `git commit`.
- [ ] Audit validator fails closed on schema/tool/registry/topology/expiry
      changes.
- [ ] Audit is zero or every residual package/advisory has one exact,
      approved, unexpired record and real follow-up.
- [ ] Exception file is absent when audit is clean.
- [ ] Dependabot has exactly Actions `/` and npm `/.github/workflows`,
      review-only.
- [ ] Final exact action roles/permissions/triggers and all P1A/P1B/P2
      enduring evidence remain green.
- [ ] Generated artifacts remain unchanged.
- [ ] Final affected/staged path set is recomputed and exact.

## Non-goals

- Upgrading external Actions without separate provenance review.
- Changing source guides/generated artifacts or writer architecture.
- Replacing the staged-content API with full-repository hook behavior.
- Auto-approving/merging dependency updates.
- Permanent/ownerless audit exceptions.
- Force, audit-force, legacy peer, or engine bypass.
