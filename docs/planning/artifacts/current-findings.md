# PSStyleGuide current findings

## Scope and method

Reviewed P1, P1A, P1B, P2, and P3 sequentially against the synchronized
TerraformStyleGuide contracts, the fresh
`docs/planning/PSStyleGuide/slate-criticism.md`, repository state, and the
primary-source research retained in
`docs/planning/artifacts/prompt-loop-primary-source-research-2026-07-30.md`.
The criticism's six recommendations remain valid; no additional issue-level
finding was identified.

## F01 — Literal P1B diagnostic authority

**Validity: confirmed.** P1B named action roles and properties but not the sole
producer, literal path, byte limit, or ordered producer→upload relationship.
That left structural policy unable to reject a newly chosen file/glob.

**Required closure:** add one Windows-cell and one writer row with exact
producer, path, collision-free name, upload inputs, conditions, no-replace
encoding/size contract, prohibited content, and mutation fixtures. Add a
filesystem-safe diagnostic key to each fixed matrix row.

## F02 — Separate observed audit facts from approval

**Validity: confirmed.** P3 combined npm-derived facts and human governance in
one exception finding. Native normalization cannot truthfully produce reason,
controls, owner, approval, or expiry.

**Required closure:** use separate `ObservedFindings`, `Approvals`,
`AuditNodePaths`, and `FollowUpEvidence` collections. Join on exact
`(Package,AdvisoryUrl)`, compare all copied facts and topology exactly, then
validate governance separately. Drift revokes approval.

## F03 — Physical non-audit P3 catalogs

**Validity: confirmed.** Node and audit catalogs were physical, but manager/
staged-hook platform cells, full Husky rows, and live-capture cases were not
fully allocated in the issue.

**Required closure:** physically allocate 16 manager, 36 staged/hook, 18 Husky
installer, and 15 live-capture cases. Every ID has one literal applicability,
fixture, identity/outcome, side effects, diagnostic, and result; reject every
catalog-cardinality mutation.

## F04 — Literal npm-operation preimage digest

**Validity: confirmed.** P3 supplied complete vectors but referenced a
canonical SHA-256 without defining the exact byte preimage or expected digest.

**Required closure:** define the bytes between the operation fences as the
BOM-less UTF-8/LF preimage with final LF and bind all consumers to literal
SHA-256
`bacd645f3b9fd5e2b740d865c64488d6853935de23c05b07639d0c9f02d8dff1`.

## F05 — Closed live GitHub retry behavior

**Validity: confirmed.** P3 bounded `Retry-After` but did not define reset/
remaining header parsing or the request budget across `/user` and `/issues`.

**Required closure:** allow three attempts per logical GET; define header
precedence, canonical integer/reset parsing, one system instant, 30-second cap,
fixed fallbacks, malformed/duplicate/date/over-cap failures, exact headers,
safe evidence, and no cached substitution. Add 15 physical capture cases.

## F06 — P1 supply freeze at P1B boundaries

**Validity: confirmed.** P1's two-gate tuple was sound, but P1B consumed it only
as general risk/action evidence and did not state exact start/pre-merge
equality.

**Required closure:** consume an immutable P1 freeze record and compare
manifest/lock blobs and hashes, Node/npm, producer argv, installed tree,
normalized audit, and decision at P1B start and immediately before merge.
Drift stops and rebaselines; P1B never refreshes dependencies.

- P1A/T1A local case counts need semantic mapping, not equality.
- PSStyleGuide staged lint and TerraformStyleGuide full lint are deliberate.
- No issue file needs to be added, deleted, renamed, or reordered.
