## Work

Reuse the accepted review command where valid. Reconcile common instructions with the two-reviewer lifecycle, user decision process and current platform capabilities. Keep platform-specific interfaces honest. Remove duplicate receipts and false claims of automatic wakeup. Do not infer a Claude tool or an outage-substitution grant from the filename.

Read [the lifecycle and convergence policy](../LOOP-POLICY.md) once. Use its source PR → review → merge → peer diff → peer repair PR → review → merge → reverse-diff loop for each actual code change. Apply [the user decision process](../DECISION-PROCESS.md) to each distinct confirmed finding. Do not create a PR for a proved no-change result. Read [parallel ownership](../ROUTING-AND-PARALLELISM.md) before assigning a writer.

## Validation

Check actual command inputs/outputs, links and native review attribution. Confirm Balanced transport and fallback remain compatible with repository AGENTS. For a new security-affecting review-policy design escalate to gpt-6-astra/high. Keep this planning branch separate from product PRs.

## Complete when

Applicable shared review instructions are consistent and byte-identical; justified platform-specific clauses are explicit. No duplicate competing orchestration policy is activated.

Historical task completion alone does not satisfy this current predicate. A conditional no-change result must include its evidence and trigger. A blocked prerequisite cannot be replaced with a success label.
