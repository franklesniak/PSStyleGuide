### Objective

### Execution controls

Apply the shared compact execution policy. Use the highest applicable risk tier. The task-specific controls below define this task's scope.

### Task-specific controls

1. Compare the PS and template documents at clause level, not section level. Read the exact blobs pinned at task start.
2. Classify each relevant clause exactly once as `TEMPLATE_EXACT`, `TEMPLATE_ADAPTED`, `PS_REQUIRED_REPOSITORY_ADAPTATION`, `PS_ONLY_SUBSTANTIVE`, `PS_ONLY_PAPERWORK`, or `UNCERTAIN_RETAIN`.
3. A proposed deletion is permitted only when the record proves `PS_ONLY_PAPERWORK`. Different wording is not proof. When a section mixes template-derived and PS-only content, isolate the smallest PS-only clause.
4. Preserve current template rules for Tier 1 fields and placement, published baseline and finalization-point synchronization, ADR Context/Decision/Consequences/Alternatives/Date semantics, and unresolved normative placeholder prohibition.
5. The record is temporary evidence, not a new governance document. Record exact source commit/tree/blob/bytes/SHA-256 and stable clause anchors.

### Procedure

1. Re-query both repositories and issue state. Create an isolated read-only worktree or object view at the PS base; read the template document from the exact current template commit/blob.
2. Extract relevant clauses with stable section/line/text hashes. Compare exact text, adapted wording, semantic requirements, repository-specific facts, examples, and older-template provenance.
3. Classify every clause affected by Tier 1 exception, metadata synchronization, URL/validator coupling, ADR status, and placeholder inspection. Record retained uncertainty explicitly.
4. Build a deletion proof that maps each planned deletion to exactly one `PS_ONLY_PAPERWORK` clause and each retained template-derived semantic to its PS destination.
5. Validate record schema, full clause coverage, unique classifications, source identities, and absence of permanent-file changes. Return the record identity and stop.

### Validation and evidence

Require current PS/template identities, one classification per relevant clause, deletion proof only for `PS_ONLY_PAPERWORK`, explicit `UNCERTAIN_RETAIN` handling, retained-template matrix, record bytes/SHA-256, and zero permanent-file/ref/public mutation.

### Stop and escalation conditions

Stop if either document changes, a clause has mixed or uncertain provenance that cannot be isolated, a deletion lacks proof, template semantics conflict, or analysis would require changing copilot-repo-template.

### Exact output

One `PS_METADATA_CLAUSE_PROVENANCE_READY` record contains the temporary path, bytes/SHA-256, exact source identities, clause counts by class, every deletion mapping, every uncertainty, and proof that no permanent bytes changed.

### Complete when

Every relevant clause has one supported class, every proposed deletion is proved `PS_ONLY_PAPERWORK`, all uncertain clauses are retained, and no permanent file changed.
