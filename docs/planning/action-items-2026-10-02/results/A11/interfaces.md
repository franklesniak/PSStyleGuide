## Closed handoff and acceptance sequence

1. Keep accepted T2 actions and generated bodies unchanged unless a demonstrated supported defect requires repair.
2. Finish A06/A07 acceptance. Compare the final generator, artifact semantic role, runtime and caller-test closure to this evidence. Reuse only unchanged proof.
3. Resolve A15's actual contract amendments and protected-path authority. Existing source inspection and this design do not answer those owner questions.
4. Freeze A16's fixed roles and actual `.mjs` paths. Implement missing T4 primitives against those roles. Do not claim a common PS consumer where none exists.
5. Run affected exact-source T2 cases on Linux when source, harness or runtime behavior changes. Re-run all16 caller cases when the artifact adapter changes. Regenerate all four outputs when normative content/generator changes, then check raw bytes/modes.
6. Let A03 wire accepted cross-host gates after its own prerequisite/authority boundary. Reject missing, failed, cancelled and skipped required cells; preserve current TF `verify` context and same-run publisher dependency.
7. Return new exact input identities, relevant actual runtime results and any changed threat assumptions to A11. The coordinator can then evaluate A11's conditional no-change predicate. A18/A19 still own final current paired reconciliation.

The current host is Windows. Node24.18.1 syntax checks succeeded against the inspected harness, but this is not execution of Linux cases. No Linux environment was installed or broad suite rerun. Windows5.1 file execution is restricted by the existing host policy; this task neither launched blocked files nor bypassed policy. Actual future5.1 validation must use an appropriate normally authorized Windows CI host and its repository workflow controls, coordinated with A03. Historical TF64 Linux success must not be used as a Windows result.
