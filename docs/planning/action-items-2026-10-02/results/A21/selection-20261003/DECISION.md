## 3. Material options before scoring

- **N — No change:** retain both implementations and the current mismatches. This preserves current operations but does not meet convergence or fix the selector gap.
- **D — Remove the checks or their hard cases:** rely on CI/review and delete the divergent validator/test responsibilities. This loses supported security and user contracts.
- **P — Use the complete landed PS implementation:** retain its production flow, public modes, strict parser boundary, transport and existing SelfTest. Add the missing staged/runtime/setup contracts within that architecture. Adapt meaningful TF tests to the same common suite. Use small explicit language facts, not parallel engines. Repair complete selector closure.
- **T — Use the complete TF implementation:** retain its production flow and inline suite, then implement all landed PS admission/finalization/proposed-policy, transport/strict JSON, recursive instruction and repaired metadata behavior in that architecture. Reconcile SelfTest extraction and selectors as part of this one implementation.
- **R — Replace both with a new generic engine/native-tool framework:** reuse parsers and Git where appropriate but redesign the validator's orchestration and test layout. This is a larger proof surface without a missing parser platform that requires it.
- **F — Defer all selection until A20 and every A07/A03 interface is accepted:** preserve the two current implementations for now. This honestly respects pending authority but unnecessarily delays ordinary decisions and work already separable from those boundaries.
- **X — Assemble independently preferred regions from both validators:** decide each helper or subsystem separately. This conflicts with the requested complete-base choice and tends to preserve incompatible parser, parent, test and transport conventions.

A verbatim PS or TF copy is the corresponding P/T option with no contract repair, so it fails the retained-contract constraints. A targeted selector-only fix is useful as P's first bounded implementation step; by itself it does not resolve the whole-validator problem. A permanent per-repository algorithm exception is N. A configuration-driven generic framework is R. Temporary holds at genuine authority/caller boundaries are part of P/T and need not defer the complete choice.
