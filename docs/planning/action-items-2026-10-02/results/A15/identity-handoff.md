# D3/D4 proposed exact identity handoff

Selected design detail for D3/D4 under the owner's D08 direction. The clear design winners are authorized for implementation. This is not an implemented adapter or Gate A/B operational approval. Native TF has none of the proposed T4 helpers. Required tests below remain obligations.

## One fixed platform adapter and explicit role arguments

Keep the single C# Win32 path/handle adapter and raw .NET collector in the canonical `SM-BACKUP-PULL-PS` source block. The permanent PS harness extracts that exact block; it does not carry a second production implementation. Generated copies come from A06's generator. The Linux wrapper uses the actual T2 Bash/GNU identity and publication operations where their contracts fit; it does not reuse `sr_run`'s inferred SR_DEST parent or jq-only state validator.

For every role, the reviewed wrapper snapshots the separately supplied `parent`, `path` and `attestation` once. It requires exact literal syntax and canonical direct-child equality before any child or creation. It proves the applicable parent/file OS properties and records expected identity. It passes those same three values, the fixed role name and exact expected identity to the fixed helper operation. It never derives a parent or changes an expected identity on mismatch. Public role values are removed from child environments; helpers have no environment fallback.

The proposed closed helper interface extends the old path-only CLI with fixed `--role`, `--parent`, `--path`, `--parent-attestation`, `--identity-kind`, `--expected-volume`, `--expected-file-id`, `--expected-length` fields for each declared input/output. POSIX identity-kind accepts device/inode decimal strings from native stat/fstat. Windows identity-kind accepts volume serial and all128 FileId bits from the retained Win32 handle; no truncation to Node's ino and no localized account/stat text. Numeric identities remain strings; fixed safe syntax and exact bounds reject coercion, signs, overflow and extra fields. A profile field is a selected closed policy, not a caller-defined limit override. Multi-input helpers have separately named copies of these fields for each role; they cannot reuse another role's tuple. Configuration/module directories use the distinct Git/directory identity interface below, not these file fields.

This argument bundle is bounded data, not a capability, signature or proof of operator approval. A fabricated bundle authorizes nothing. The wrapper and helper must perform their actual applicable inspections and compare to the declared expected identity. On Windows, the retained read guard below binds a helper's read to the wrapper-inspected identity; the helper never claims that Node alone proved a128-bit Win32 ID. Success remains provisional until wrapper post-read checks finish. Free path-only invocation, wrong platform/role/operation, alias, missing field, unsupported inspection, reused role or changed identity fails closed in the composite wrapper/helper contract. A Node-only Windows invocation cannot prove the retained guard or all128 Win32 identity bits. Its parse result or exit0 alone is not a completed identity/publication pass; only the reviewed wrapper's actual pre/post handle checks can complete that proof. No unforgeable cross-process proof token is claimed.

## Windows capture  to  validation  to  publication

1. Resolve the reviewed Node and Terraform executables by exact path/version/hash. Select bounded policy before path creation. The inspector owns the common tokenizer and one limits definition; a fixed built-in-only `policy` operation can return only that closed numeric policy to the .NET collector. It cannot run a user command or read state. This proposed interface must be tested with5.1 and7; it is not a new npm dependency.
2. Walk the canonical parent components no-follow. Prove volume/type/reparse and exact SID/DACL properties. Create the raw candidate once with `CreateNew`, write-only access and `FileShare.None`. Retain its SafeFileHandle. Record volume/128-bit FileId, nlink1, ACL, length0 and the one invocation-context parent identity.
3. Use the one raw .NET bounded collector on both editions. It launches only the fixed nonmutating operation, drains stdout/stderr concurrently, writes raw bytes through this handle, applies writable backpressure and enforces the inspector's selected byte/deadline/stderr limits. It never converts state bytes into PowerShell strings. Complete native exit, stream drains, flush and close evidence is required. Stderr byte65537 fails73; retain no stderr payload beyond65536 and never print it. Failure metadata keeps native outcome distinct from the helper status.
4. Finish capture and record the byte count/digest from those exact raw bytes. Close the exclusive writer only after capture/ACL/identity checks. Reopen the same candidate no-follow through the Win32 adapter with read access and `FileShare.Read` only. Inspect the actual opened handle and require the original volume/128-bit FileId, nlink1, type, ACL, length and digest. Refuse a close, reopen, inspection or identity error; never refresh the expected tuple. The close/reopen interval has no continuous exclusive handle. Its safety still requires the operator's no-authorized-competing-writer attestation; there is no hostile namespace-confinement claim.
5. Retain this read guard for the full helper read. Read sharing permits the tokenizer's read but denies new write/delete access; the wrapper checks the same opaque Win32 identity before and after. Capture `terraform show -json` through the same .NET collector into its separate helper-private show identity, with its own write to read handoff and show bound. A fixed `validate-captured` inspector operation tokenizes the guarded raw/show streams completely and performs no Terraform spawn on Windows. The Linux adapter continues to use the bounded Node collector for fixed capture/show operations. Do not duplicate the tokenizer or silently invoke Node capture against FileShare.None.
6. Require helper native exit0, complete strict tokenization and matching projected count/digest/metadata. Reinspect every retained handle and named path. Close read guards before hard-link publication. Reinspect the original candidate and fresh final absence, then make one actual CreateHardLinkW call. On NTFS, inspect both names for the original volume/FileId, ACL, byte/digest equality and link count2; remove only the exact temporary name; reopen final and prove count1. On ReFS or unsupported publication, retain validated temporary evidence and leave a previously absent final absent. Never fall back to copy/move/retry. After uncertain publication retain all remaining names.

FileShare semantics and the NTFS-only hard-link limit are documented by [Microsoft FileShare](https://learn.microsoft.com/en-us/dotnet/api/system.io.fileshare?view=netframework-4.8.1) and [CreateHardLinkW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createhardlinkw). The retained read-guard application is a design inference requiring actual platform tests. The earlier coordinator EBUSY probe proves only the incompatible exclusive writer/Node reopen, not this replacement.

Windows child-tree termination remains a required implementation proof: bound start/drain/descendants/inherited pipes and prove completion without advertising POSIX graceful signals. A reviewed process-tree mechanism must work on5.1 as well as7; unsupported assignment/termination or unclosed streams cannot pass. No Win32 job-object implementation or termination experiment is claimed here. Linux retains its separate TERM5000ms/KILL/drain contract. This unresolved platform proof prevents GateA acceptance even if the data handoff is structurally agreed.

## D3a: Select a concrete Windows child lifetime mechanism

**Validate.** The proposed collector lacked a complete mechanism for child lifetime and inherited pipes on both Windows editions. Killing only the direct process can leave an inherited writer alive. PowerShell5.1's .NET Framework also cannot assume the newer Process.Kill(entireProcessTree) interface. Independent review then identified a creation-phase gap in option D: parent death between suspended creation and job assignment can strand the child. Microsoft describes that exact failure and the creation-time job-list solution. This refines the same lifetime finding and its rubric; it is not evidence of a production Terraform incident.

**Options before the rubric.** A: kill only the direct Process. B: enumerate descendant PIDs and kill them after launch. C: require the newer .NET tree-kill method and omit5.1. D: create a suspended child, then assign it to a private Job Object. E: install a separate supervisor service. F: omit Windows capture. G: assign the private job during CreateProcessW through PROC_THREAD_ATTRIBUTE_JOB_LIST, with explicit inherited handles and bounded stream completion. A job assigned after the child starts also has B's running-child race. Using an existing parent in the job needs an anchor process; safely creating that anchor repeats the same problem unless supplied by E or G. A service with its own job is E, with installation and authority costs. Breakaway or unbounded pipe waits invalidate every option.

**Stakeholders and rubric.** Operators and UX need a bounded stop with clear retained-evidence status. QA needs deterministic child/grandchild, assignment-failure and inherited-pipe cases on both editions. Runtime/security engineers need no launch-before-assignment race or leaked handles. Maintainers need no service deployment. Weights are lifetime control35 (the reviewed native child tree starts only under the selected control), bounded drain/failure25 (no successful return before complete exit/stream closure), edition compatibility20 (actual5.1 and7 APIs), observable refusal15 (unsupported or uncertain outcomes remain failure), and maintenance burden5. Scores1–5 mean fundamental gap, major limits, workable with material limits, strong bounded tradeoff, and full design coverage respectively;0 means the capability is omitted. Hard constraints: no7-only substitute, no privilege/service installation, no unbounded drain, no false POSIX signal claim, and no claim to contain arbitrary broker-created processes.

| Option | Lifetime35 | Drain25 | Editions20 | Refusal15 | Burden5 | Total |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A direct child only | 1 | 1 | 5 | 2 | 5 | 43 |
| B post-launch PID traversal | 3 | 2 | 4 | 2 | 4 | 57 |
| C newer .NET tree kill only | 3 | 3 | 1 | 4 | 4 | 56 |
| D suspended launch, then job assignment | 2 | 4 | 5 | 2 | 3 | 63 |
| E external supervisor | 4 | 5 | 3 | 3 | 1 | 75 |
| F omit Windows | 0 | 0 | 0 | 1 | 5 | 8 |
| G job assignment during creation | 5 | 5 | 5 | 4 | 3 | 95 |

**Selected instructions.** Use G in the existing Windows adapter. Require Windows 10 or Windows Server 2016, or a later supported version. Keep support for PowerShell 5.1 and PowerShell 7. Create a private Job Object. Set KILL_ON_JOB_CLOSE. Do not permit breakaway. Add its handle to PROC_THREAD_ATTRIBUTE_JOB_LIST before CreateProcessW. Use STARTUPINFOEX and EXTENDED_STARTUPINFO_PRESENT. Add the explicit stdin, stdout and stderr handles through PROC_THREAD_ATTRIBUTE_HANDLE_LIST. Keep the job handle and parent read handles noninheritable. Use CREATE_SUSPENDED and an explicit executable path. Supply only the reviewed environment and working directory. If an attribute or creation operation fails, refuse the operation. Do not use separate creation and assignment as a fallback. After creation, confirm job membership before ResumeThread. If confirmation or resume fails, terminate the job and verify completion. Keep the job handle until completion checks finish. At the deadline, terminate the job. Require native exit, zero active job processes, completed stream reads and closed output handles. Use a bounded 5000 ms termination and drain interval after the operation deadline. If completion cannot be established, return failure and retain uncertain evidence. Do not retry the operation. Keep Linux signal handling separate.

This supports the fixed reviewed Terraform/native-child launch path, not hostile process containment. Microsoft documents that broker-created Win32_Process children need not join the job. No broker or external supervisor is an allowed collector operation. Actual selected tool/plugin launch behavior must be verified before Gate A; unexplained detached processes or inherited pipes prevent acceptance. Do not equate a job completion notification alone with proof: query actual accounting and stream completion. Unsupported nested-job assignment refuses before child execution.

**References and pending proof.** [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) documents inheritance, exceptions, termination and close behavior. [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw) defines executable and launch controls. [UpdateProcThreadAttribute](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) documents the job and handle lists and the Windows 10/Server 2016 platform floor. [Microsoft's creation-time assignment explanation](https://devblogs.microsoft.com/oldnewthing/20230209-00/?p=107812) directly confirms the suspended-child gap and selected solution. These contracts support the design, not executed adapter evidence. Gate A must run both PowerShell editions on supported Windows hosts. Cases must cover parent death before creation, during creation, after successful creation before resume, and during child execution. An external observer must prove no orphan; a killed wrapper has no success result. Also require unsupported-attribute refusal, immediate grandchildren, inherited pipes, job-list/ResumeThread failures, native nonzero, no-breakaway refusal, deadline and complete drain. A16 owns implementation and those tests.

## D4 separate role allocation and fixed operations

Retain all original T4-STATE-ROLES-v1 rows and lifetime rules. Add these declared roles to the same table before implementation; do not create a second role framework:

| Prefix | Creator/consumer and identity | Bound/lifetime |
| --- | --- | --- |
| DIFF_MANIFEST | Existing operator/peer-reviewed manifest  to  difference helper; own parent/path/attestation and immutable identity | 1..16MiB; retain review input; never overwrite/delete |
| DIFF_CURRENT_SHOW | Fixed show collector on current raw state  to  difference helper; separate fresh protected capture and raw-state/tool binding | 1..selected show limit; retain until reviewed disposition; partial cleanup only exact owned |
| DIFF_PROPOSED_SHOW | Fixed show collector on proposed raw state  to  difference helper; never alias current show/state | Same bound and separate lifetime |
| DIFF_PROVIDER_SCHEMA | Fixed providers-schema collector  to  difference helper; exact Terraform/provider/lock/config binding | 1..selected show limit proposed; complete strict format/version validation and operator-reviewed no-network identity; retain until disposition |
| RM_RECHECK_MATCH | Fixed second state-list collector  to  resolver/confirmation; separate fresh tuple, not RM_MATCH reuse | 1..65536bytes, at most1024 records, max2048bytes/address; compare exact address+LF and digest; exact-owned cleanup only |
| LOCAL_CORRUPTION_SOURCE | Original explicit SOURCE_PARENT/SOURCE/SOURCE_ATTESTATION; paused source-writer exclusion, ordinary source uid/mode/nlink/hash and identity | Selected D5 0..S bound and source retention; keep the distinct paused-writer attestation, not destination-private attestation |

The five new prefixes use their own `_PARENT`, `_PATH`, `_PARENT_ATTESTATION`. Corrupt-source field names/literal stay exactly as original. The source can be local active-state storage; do not infer its parent from the protected preservation destination or add an invented outside-VCS source guarantee. Every existing state backup, proposed/desired input, fresh verification pull, report, recovery output and local command backup keeps its own role. Private capture/show/index files remain beneath the one validated invocation context, never ambient temp or caller-named private paths. HMAC indexes stay helper-private, max256MiB, with the per-run256-bit key only in memory; no key/HMAC/leaf value in evidence.

The configuration-root interface is a directory plus full Git object-format/commit/tree, exact stage0 path/mode/blob/raw working-hash rows and clean worktree/untracked proof. Module roots have exact source/version/resolved-directory/tree identities; .terraform.lock.hcl and provider-schema/tool identities must match the approved manifest. Do not treat a directory as a file tuple, parse HCL to invent subject authority, infer parent from it, or regard Git cleanliness as human review. Unknown/dynamic subject identity rejects. The manifest remains operator-and-peer-reviewed.

Use the same bounded collector core behind these fixed operations only:

| Operation | Fixed child/output | Proposed bound and authority |
| --- | --- | --- |
| workspace-show | `terraform workspace show`; no user argv | Max91bytes for the approved90-byte workspace plusLF; exact workspace grammar; empty stderr |
| state-pull | `terraform state pull` | Selected raw S, complete strict state4 metadata/tokenization; stderr65536 |
| show-json | `terraform show -json <the guarded raw-state role>` | Selected show limit, supported show format fully tokenized; stderr65536 |
| state-list | `terraform state list <the already parsed one address>` | 65536bytes/1024 LF records/2048bytes per address; empty stderr; exact singleton bytes |

| rm-dry-run | `terraform state rm -dry-run <the already parsed one address>` | 65536bytes proposed discarded raw stdout; empty stderr; native start/exit0; no localized output interpretation |

All operations use exact resolved executable, reviewed working-directory identity, closed stdin, shellfalse, the selected deadline and original native-failure distinction. No caller executable/argument array, fixture switch, force, lock-disable, mutation operation or user command string is exposed by the GateA collector. Unknown operations and wrong output role reject before child/path creation. The small-output/provider-schema limits are selected D4 design details; implementation and boundary tests remain due. Pinned actual Terraform help/schema compatibility must be proved before freezing executable fixtures.

## Required handoff negatives

GateA must exercise real raw-byte/ACL/identity behavior on5.1/7: exclusive writer blocks Node reopen; reviewed read-sharing path accepts; capture-close failure; replacement during the close/reopen gap; same path with different FileId; wrong volume; nlink>1; ACL/reparse/owner drift; digest-only change with same identity; writer/delete attempt while guard held; helper wrong role/tuple/platform, missing fields, unknown operation/argv and aliased inputs; original/child/file identities before and after all reads; Node/show/native failure; byte/deadline/stderr/read/write/flush/close boundaries; orphan/inherited-pipe termination; real no-clobber/race/NTFS and ReFS refusal. Each invalid prerequisite has zero mutation calls, no secret output and the exact D5-dispositioned retained path/native outcome. Existing SR oracles and their status74 stay unchanged.

Approval binds the actual implemented versions/blobs/tree, complete role table, policy limits, runtime/tool identities, all applicable exact case/cell results and both real people. A wrapper's argument record or this design hash is not that approval. GateB consumes the frozen helpers/roles/catalog; any changed approved code/role/schema/path/limit/confirmation/evidence returns toGateA. A proposed B-only edit to a shared source/harness file does not itself exempt its changed blob from the actual approval binding.
